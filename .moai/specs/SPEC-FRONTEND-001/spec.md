# SPEC-FRONTEND-001: Frontend Web Public Viewer Interface for Junpa

## History

## 1. Environment

- **Platform:** Web application (Next.js App Router)
- **Framework:** React 19 with Next.js 15.x (TypeScript)
- **Styling:** Tailwind CSS with Radix UI and Shadcn/ui components
- **API Backend:** Junpa Streamer Service (SPEC-STREAM-001) via REST API
- **Video Playback:** HTML5 Video element with HLS.js for adaptive streaming
- **Target Browsers:** Chrome 120+, Firefox 120+, Safari 17+, Edge 120+ (including mobile browsers)
- **Target Devices:** Desktop, tablet, and mobile (responsive design, mobile-first)
- **Deployment:** Vercel (serverless edge functions, ISR support)
- **Authentication:** Optional Google OAuth 2.0 for personalization features (reactions, personalized URLs)

## 2. Assumptions

- The Streamer Service (SPEC-STREAM-001) is operational and serves the documented API endpoints
- The Admin Web (SPEC-ADMIN-001) has populated `/.junpa/library.json` with video, playlist, series, and featured content metadata
- The Frontend Web does NOT directly access Google Drive; all data flows through the Streamer Service API
- Video files are in web-compatible formats (mp4, webm) playable by HTML5 video with HLS support
- Shareable URLs generated by the Streamer Service are the primary entry point for viewers
- The majority of viewers are anonymous; authentication is optional for basic viewing
- Mobile traffic is expected to be significant (50%+ of total traffic)
- Network conditions vary; graceful degradation for slow connections is essential
- Content library size is moderate (hundreds to low thousands of videos per channel)

## 3. Requirements

### Module 1: Content Discovery and Browsing

**R1.1 Ubiquitous:** The system shall always display content in a responsive layout that adapts to desktop (3-4 columns), tablet (2 columns), and mobile (1 column) viewports.

**R1.2 Event-Driven:** WHEN a viewer navigates to the home page THEN the system shall fetch and display featured content, active live channels, and recent video additions from the Streamer Service API.

**R1.3 Event-Driven:** WHEN a viewer navigates to the video library page THEN the system shall fetch all available video assets with thumbnail, title, duration, and tags.

**R1.4 Event-Driven:** WHEN a viewer enters a search query THEN the system shall filter displayed content by matching titles and tags in real time.

**R1.5 State-Driven:** IF the content library is empty THEN the system shall display a friendly "No content available yet" message with the channel owner's branding.

**R1.6 Optional:** Where possible, the system shall provide tag-based filtering and category grouping for content discovery.

---

### Module 2: Video Playback (On-Demand)

**R2.1 Event-Driven:** WHEN a viewer selects a video THEN the system shall fetch video metadata and streaming URL from the Streamer Service and begin playback.

**R2.2 Ubiquitous:** The system shall always display a video player with play/pause, seek bar, volume control, fullscreen toggle, and playback speed selector.

**R2.3 Ubiquitous:** The system shall always display video metadata (title, description, tags, duration) alongside the player.

**R2.4 Event-Driven:** WHEN a viewer seeks to a specific timestamp THEN the system shall request the appropriate segment from the Streamer Service and resume playback within 2 seconds.

**R2.5 State-Driven:** IF the video stream fails to load THEN the system shall display a user-friendly error message with a retry button.

**R2.6 Unwanted:** The system shall NOT auto-play videos with audio unmuted unless the viewer has explicitly initiated playback.

**R2.7 Optional:** Where possible, the system shall support Picture-in-Picture (PiP) mode for continued viewing while browsing.

---

### Module 3: Live Playlist (Channel) Viewing

**R3.1 Event-Driven:** WHEN a viewer accesses a live playlist channel THEN the system shall fetch the current playback state (current video, seek position, time until next) from the Streamer Service.

**R3.2 Event-Driven:** WHEN a viewer joins a live channel THEN the system shall start playback at the calculated current position, synchronized to the channel's timeline.

**R3.3 Event-Driven:** WHEN the current video in a live playlist ends THEN the system shall automatically fetch the next video from the Streamer Service and transition playback seamlessly.

**R3.4 State-Driven:** IF a live playlist status is "coming_soon" THEN the system shall display a countdown timer showing time until the channel goes live.

**R3.5 State-Driven:** IF a non-looping live playlist status is "ended" THEN the system shall display a "This channel has ended" message with a link to browse other content.

**R3.6 Ubiquitous:** The system shall always display a "LIVE" badge on active live playlist channels.

**R3.7 State-Driven:** IF a live playlist has loop enabled AND playback reaches the end THEN the system shall continue playback from the beginning without viewer intervention.

---

### Module 4: Series Playback

**R4.1 Event-Driven:** WHEN a viewer selects a series THEN the system shall display the series overview with episode list, episode numbers, titles, and durations.

**R4.2 Event-Driven:** WHEN a viewer starts playing an episode in a series THEN the system shall load the video player with the selected episode.

**R4.3 State-Driven:** IF auto-play is enabled for the series AND the current episode ends THEN the system shall automatically start the next episode after a 5-second countdown with a "Next Episode" preview.

**R4.4 Event-Driven:** WHEN a viewer clicks "Next Episode" or "Previous Episode" THEN the system shall navigate to and begin playback of the corresponding episode.

**R4.5 Ubiquitous:** The system shall always highlight the currently playing episode in the series episode list.

**R4.6 Optional:** Where possible, the system shall remember the viewer's last watched episode position and offer to resume.

---

### Module 5: Viewer Reactions

**R5.1 Event-Driven:** WHEN a viewer clicks the "Like" button on a video THEN the system shall increment the like count and update the display.

**R5.2 Ubiquitous:** The system shall always display the current view count and like count for each video.

**R5.3 Unwanted:** The system shall NOT allow a single viewer to submit more than one like per video per session.

**R5.4 State-Driven:** IF the viewer has already liked a video in the current session THEN the system shall display the like button in an "active" state and disable further likes.

**R5.5 Optional:** Where possible, the system shall persist reaction state across sessions for authenticated viewers.

---

### Module 6: Shareable URL Access

**R6.1 Event-Driven:** WHEN a viewer accesses a shareable URL (/s/{token}) THEN the system shall validate the token via the Streamer Service and load the corresponding content.

**R6.2 Event-Driven:** WHEN a viewer accesses a shareable live playlist URL THEN the system shall load the live playlist at the current playback position.

**R6.3 State-Driven:** IF the shareable URL token is expired or invalid THEN the system shall display a "This link has expired" page with the channel owner's branding.

**R6.4 Ubiquitous:** The system shall always provide a share button that copies the current content's shareable URL to the clipboard.

---

### Module 7: Personalized Channel URLs

**R7.1 Event-Driven:** WHEN a viewer navigates to /{username} THEN the system shall load that user's public channel page with their featured content and library.

**R7.2 State-Driven:** IF the username does not exist THEN the system shall display a 404 page with a suggestion to check the URL.

**R7.3 Ubiquitous:** The system shall always display the channel owner's name and branding on personalized channel pages.

---

### Module 8: Performance and Accessibility

**R8.1 Ubiquitous:** The system shall always achieve a Lighthouse Performance score of 90 or above.

**R8.2 Ubiquitous:** The system shall always meet Core Web Vitals thresholds: LCP < 2.5s, FID < 100ms, CLS < 0.1.

**R8.3 Ubiquitous:** The system shall always comply with WCAG 2.1 AA accessibility standards, including keyboard navigation and screen reader support.

**R8.4 Ubiquitous:** The system shall always use Server-Side Rendering (SSR) or Incremental Static Regeneration (ISR) for initial page loads to ensure SEO and fast time-to-interactive.

**R8.5 Ubiquitous:** The system shall always lazy-load images and non-critical components below the fold.

**R8.6 Unwanted:** The system shall NOT block the main thread for more than 200ms during initial page render.

**R8.7 Optional:** Where possible, the system shall support a dark mode theme toggle.

## 4. Specifications

### 4.1 Data Models (Frontend Types)

The following TypeScript interfaces define the Frontend Web's internal data structures, derived from the Streamer Service API responses:

```typescript
// Streamer API Response Types

interface VideoMetadata {
  id: string;                     // UUID v4
  title: string;
  description?: string;
  duration: number;               // Duration in seconds
  format: "mp4" | "webm";
  stream_url: string;             // Google Drive streaming URL (from Streamer)
  thumbnail_url: string | null;
  tags: string[];
  reactions: ReactionData;
}

interface ReactionData {
  likes: number;
  views: number;
}

interface LivePlaylistState {
  playlist_id: string;
  title: string;
  description?: string;
  status: "coming_soon" | "live" | "ended";
  countdown_seconds: number | null;  // When status = "coming_soon"
  current_video: VideoMetadata | null;  // When status = "live"
  seek_position: number | null;      // Seconds to seek to
  time_until_next: number | null;    // Seconds until next video
  total_videos: number;
  current_index: number | null;
  is_looping: boolean;
}

interface SeriesInfo {
  id: string;
  title: string;
  description?: string;
  episodes: EpisodeInfo[];
  auto_play: boolean;
}

interface EpisodeInfo {
  video_id: string;
  episode_number: number;
  title?: string;
  duration: number;
  thumbnail_url: string | null;
}

interface FeaturedContent {
  content_type: "video" | "playlist" | "series";
  content_id: string;
  title: string;
  description?: string;
  thumbnail_url: string | null;
  priority: number;
}

interface ChannelInfo {
  username: string;
  display_name: string;
  featured: FeaturedContent[];
  live_channels: LivePlaylistState[];
  recent_videos: VideoMetadata[];
  series_list: SeriesInfo[];
}

// Client-side state types

interface ViewerSession {
  is_authenticated: boolean;
  google_account_id?: string;
  display_name?: string;
  liked_videos: Set<string>;      // Video IDs liked in this session
}

interface PlayerState {
  is_playing: boolean;
  current_time: number;
  duration: number;
  volume: number;
  is_muted: boolean;
  is_fullscreen: boolean;
  playback_rate: number;
  is_pip: boolean;
  buffered_ranges: Array<{ start: number; end: number }>;
  error: string | null;
}
```

### 4.2 Page Routing Structure

```
app/
  layout.tsx                       # Root layout with theme, fonts, analytics
  page.tsx                         # Landing page (redirect to default channel or explore)

  [username]/                      # Personalized channel URL
    layout.tsx                     # Channel layout with branding header
    page.tsx                       # Channel home: featured + live + recent
    videos/
      page.tsx                     # Full video library browse
    series/
      page.tsx                     # Series listing
      [seriesId]/
        page.tsx                   # Series detail with episode list
    live/
      [playlistId]/
        page.tsx                   # Live playlist viewer

  watch/
    [videoId]/
      page.tsx                     # On-demand video player page

  s/
    [token]/
      page.tsx                     # Shareable URL resolver

  not-found.tsx                    # Custom 404 page
  error.tsx                        # Global error boundary
```

### 4.3 Module Dependency Diagram

```
                    +-------------------+
                    |  Shareable URL    |
                    |  Access (Mod 6)   |
                    +--------+----------+
                             |
                    resolves to content
                             |
              +--------------+--------------+
              |              |              |
    +---------v----+  +------v------+  +---v-----------+
    | On-Demand    |  | Live        |  | Series        |
    | Playback     |  | Playlist    |  | Playback      |
    | (Module 2)   |  | (Module 3)  |  | (Module 4)    |
    +-------+------+  +------+------+  +------+--------+
            |                |                |
            +-------+--------+--------+-------+
                    |                 |
          +---------v------+  +-------v--------+
          | Content        |  | Viewer         |
          | Discovery      |  | Reactions      |
          | (Module 1)     |  | (Module 5)     |
          +--------+-------+  +----------------+
                   |
          +--------v--------+
          | Personalized    |
          | Channel URLs    |
          | (Module 7)      |
          +---------+-------+
                    |
          +---------v--------+
          | Performance &   |
          | Accessibility   |
          | (Module 8)      |
          +------------------+
```

**Dependency Summary:**
- Module 6 (Shareable URLs) resolves to Modules 2, 3, or 4 depending on content type
- Modules 2, 3, and 4 are the core playback modules and share the video player component
- Module 1 (Discovery) feeds content to playback modules
- Module 5 (Reactions) is integrated within playback modules
- Module 7 (Channel URLs) wraps Module 1 with user-specific context
- Module 8 (Performance/Accessibility) is cross-cutting across all modules

### 4.4 API Integration Points (Streamer Service)

```
Streamer Base URL: {STREAMER_API_BASE}/api/v1

Content Discovery:
  GET    /stream/{video_id}           - Video metadata + streaming URL
  GET    /live/{playlist_id}          - Live playlist current state
  GET    /live/{playlist_id}/next     - Next video in live playlist

Shareable URLs:
  GET    /s/{token}                   - Resolve shareable token to content
  GET    /s/{token}/live              - Resolve shareable token to live state

Health:
  GET    /health                      - Streamer service health check

Note: The Frontend Web requires additional "browse" endpoints
      from the Streamer Service that may need to be added:
  GET    /channel/{username}          - Channel info (featured, live, recent)
  GET    /channel/{username}/videos   - All videos for a channel
  GET    /channel/{username}/series   - All series for a channel
  GET    /series/{series_id}          - Series detail with episodes
```
